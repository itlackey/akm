# AKM CLI and product surface recommendations

Release plan from the CLI review and the review of `release/0.11.0` at `4b44628eb`. Checked items are implemented on this branch; the first released version remains to be recorded in the migration guide.

The first additive doctor entry points are also implemented: `doctor` mirrors health, and `doctor metrics`, `info`, `log`, and `judge` reuse their existing handlers. Improve-run reporting and the remaining doctor consolidation are still planned.

**0.10.x** is the target for every compatible fix and additive replacement, including usage metrics; **0.11** removes the deprecated surface and makes incompatible default/result changes. Keep existing commands, flags, config keys, output contracts, and input interpretation working throughout 0.10.x. Introduce replacement behavior through new explicit inputs first; do not hide a breaking change inside an addition. `STABILITY.md` records the scheduled removals, and the migration guide records first supporting versions.

**Doctor boundary:** All reporting, health, metrics, and developer diagnostics belong under `akm doctor` in 0.11, with focused subcommands for distinct jobs. This power-user surface can evolve faster than the normal CLI; ordinary operation results, lifecycle status, and previews such as `--dry-run` remain with their commands.

**Learning boundary:** In both 0.10.x and 0.11, simplify improve and related automation/learning interfaces without changing their internals, effective defaults, or behavior. Preserve process selection/order, prompts, model requests, eligibility, judgment, acceptance, writes, publication, and evaluation history; CLI/config changes must feed the existing implementations equivalent inputs. This supersedes the earlier proposals to replace the strategy engine, make improvement proposal-only, unify autonomy policies, or change what `setup --learning off` disables.

## CLI cuts and refactors

- [ ] **[0.11] Remove the standalone `judge` and any remaining `improve judge` entry point in favor of `doctor judge`.** Internal model evaluation belongs in the power-user diagnostic surface.
- [ ] **[0.11] Remove `improve --show-prompt` in favor of `doctor prompt`.** Prompt inspection should remain available without enlarging the normal improvement interface.
- [ ] **[0.11] Remove top-level `health` in favor of bare `doctor`, with reporting and comparison controls under `doctor metrics`.** Routine diagnosis gets a simple entry point while advanced analysis remains encapsulated under the same namespace.
- [ ] **[0.11] Remove top-level `metrics` in favor of `doctor metrics`.** Usage, outcome, and cost analysis should not compete for space in the normal CLI.
- [ ] **[0.11] Remove `task doctor` after its diagnostics are available through `doctor`.** A second diagnostic entry point adds discovery cost without a separate user job.
- [ ] **[0.10.x add; 0.11 remove] Replace `improve report` with `doctor metrics`, preserving run/window selection and usage, routing, and cost data.** Improvement reporting belongs with the other diagnostic reports.
- [ ] **[0.11] Put every reporting command, mode, and human report table under doctor, including improve's automatic post-run usage table, while preserving recorded data and structured operation results.** A consistent reporting boundary keeps normal command output focused without changing learning internals or evaluation evidence.
- [ ] **[0.11] Move top-level `info` and `log` to `doctor info` and `doctor log`.** Installation inspection and diagnostic event analysis belong beside the other power-user tools.
- [ ] **[0.11] Replace `task explain` and `workflow plan` with `doctor explain <ref>`, retaining ordinary mutation previews such as `--dry-run` on their commands.** Detailed execution inspection belongs under doctor while checking an operation before applying it remains part of normal use.
- [x] **[0.10.x] Give new `doctor` subcommands an explicit evolving contract, preserving error/exit conventions, credential redaction, and specific machine fields promised to consumers.** The compatibility boundary must be clear from the first release of the replacement.
- [ ] **[0.11] Keep JSON and text as general output formats, remove YAML, and limit Markdown to reports and JSONL to operations where streaming is useful.** Each supported format should solve a concrete consumption problem instead of multiplying every command's presentation variants.
- [ ] **[0.11] Remove global `--output` in favor of stdout and shell redirection.** File delivery does not need a parallel CLI mechanism for every renderer.
- [ ] **[0.11] Remove global `--detail` and replace its useful behaviors with explicit per-command controls for limits, context budgets, and outlines.** Users should understand what a control changes without learning command-specific meanings of brief, normal, and full.
- [ ] **[0.10.x audit/aliases; 0.11 removal] Retire `remember --auto` and `--enrich`, first providing experimental configuration for demonstrated research uses of the same enrichment path.** Reducing capture options does not justify moving enrichment into a different learning process.
- [ ] **[0.11] Remove `remember --show-similar` and use retrieval for similarity checks.** Saving and searching are already distinct operations and do not need a combined capture mode.
- [ ] **[0.10.x aliases; 0.11 old-path removal] Move custom strategy definitions and research-only process tuning under `experimental`, keeping the existing strategy engine and selection behavior.** Ordinary users should not need pipeline internals, while evaluations still need to isolate and tune processes.
- [ ] **[0.11] Move `improve --require-feedback-signal` into experimental configuration only after preserving its per-run scope, precedence, and exact eligibility behavior for existing callers.** Removing a research switch must not silently enable additional maintenance work.
- [ ] **[0.11] Remove `improve --json-to-stdout` once the ordinary JSON output exposes the run data evaluators consume, preserving persisted results and telemetry.** A redundant output switch can disappear without depriving research of its evidence.
- [ ] **[0.11] Simplify bulk proposal controls only where the existing drain/accept handlers can retain identical selection, judgment, and side effects; retain explicit-ID accept/reject.** Similar-looking commands are not interchangeable when they apply different approval rules.
- [ ] **[0.11] Remove `upgrade --next` and use `--channel` to select a coordinated CLI-and-plugin release channel.** Two prerelease selectors with different plugin behavior make upgrades difficult to predict.
- [ ] **[0.11] Remove `agent <ref>`, `command run <ref>` / `command <ref>`, `task run`, and `workflow run` after `akm run <ref>` has shipped in 0.10.x.** The compatibility period lets consumers migrate before execution is consolidated under one command.
- [ ] **[0.11] Remove the no-ref interactive agent launcher.** Starting another agent CLI without using an AKM asset provides little AKM-specific value.
- [ ] **[0.11] Make `curate` return bounded packed context by default, preserve refs and selection reasons, and replace the optional `--pack` mode with a normal token-budget control.** Curate should deliver usable context while search handles candidate discovery.
- [ ] **[0.11] Remove `search --by-usage` after its usage-ranking functionality is available through `doctor metrics`.** Search should consistently interpret its query rather than silently switch jobs.
- [ ] **[0.11] Remove `task add` and import validated task definition files, leaving new tasks disabled until `task enable` and preserving activation when updating existing tasks.** Tasks are assets and do not need a parallel CLI authoring system; this replaces the earlier proposal to keep a reduced `task add`.
- [ ] **[0.11] Remove `task sync` after its maintenance capabilities ship under `doctor scheduler sync` in 0.10.x.** Host scheduler repair belongs with administration, and bare doctor must not mutate scheduler entries.
- [ ] **[0.11] Remove `task prune`, folding required cleanup of owned orphan scheduler entries into the migration/reconciliation path.** A separate pruning command duplicates scheduler maintenance; unrelated installations' entries must remain untouched.
- [ ] **[0.11] Remove `task history` after its task/ref, bundle, time-window, and limit selection ships in `doctor log`; use `doctor metrics` for aggregates.** Per-run investigation should share the diagnostic surface without losing task identity or execution evidence.
- [ ] **[0.11] Leave `task enable`, `task disable`, and the scheduler's `task dispatch` entry point as the task family after moving execution and diagnostics.** These are distinct scheduling operations, while generic search/show already discover and inspect task assets.
- [ ] **[0.11] Remove `clone` after `import` accepts its asset refs and preserves asset type, companion files, provenance, and destination behavior in 0.10.x.** Users should choose the source to bring in rather than decide between two copying commands.
- [ ] **[0.10.x additions; 0.11 incompatible cleanup] Unify import's common destination/name/overwrite controls and retain `--bundle` versus unmanaged `--dest`; require an explicit new input form when typed import would reinterpret an existing document input.** The 0.10.x additions are implemented as `--asset-ref` and `--type task`, with shared `--name`/`--force`/`--bundle` and asset-only `--dest`; incompatible cleanup remains for 0.11.
- [ ] **[0.11] Remove `search --include-proposed` and `--include-sessions` after repeatable `--include key=value` ships in 0.10.x, initially supporting `quality=proposed` and `type=<excluded-type>`.** One inclusion control can restore normally hidden categories without adding a boolean for every category.
- [x] **[0.10.x] Make the new `--include` relax only the named default exclusions while retaining query matching, source/project boundaries, explicit filters, and type selection.** An inclusion option should expand eligible categories without becoming an unrestricted OR that bypasses the caller's constraints.
- [ ] **[0.11] Make `lint` exit nonzero for errors and remove `--fail-on-flagged`.** A validation command should signal failed validation without an additional opt-in flag.
- [ ] **[0.11] Remove `--timeout-ms` after duration-based `--timeout` is supported throughout.** Keeping two equivalent timeout interfaces would preserve the inconsistency the replacement is meant to remove.
- [ ] **[0.10.x new interfaces; 0.11 legacy tightening] Reject invalid values and incompatible flag combinations instead of silently substituting behavior, retaining existing documented compatibility during 0.10.x.** New interfaces can be strict immediately without unexpectedly breaking old scripts in a patch release.
- [ ] **[0.11] Rename session extraction's source-selector `--type`, keeping it distinct from the execution `--harness` selector.** `--type` should consistently mean asset type rather than sometimes identifying the source of session logs.

## Show argument review

All declared show arguments and shared flags were checked in the current 0.10 tree and the reviewed 0.11 snapshot. Proposed names below are migration targets, not installed syntax.

| Argument | Recommendation and reason |
| --- | --- |
| `<ref>[#fragment]` | **[0.10.x / 0.11] Keep one ref, returning its full body or exact selected section by default.** A read should not need a verbosity preset to return the requested content. |
| `--context exact\|lead` | **[0.10.x add; 0.11 remove old mode] Add `--lead` for the document introduction on a Markdown fragment; exact remains the default.** A single optional behavior does not need a two-value mode. |
| `--max-tokens` | **[0.10.x fix; retain in 0.11] Apply the budget independently to whole documents, exact fragments, and lead-plus-fragment reads; disclose estimation and truncation.** Context size is a useful control regardless of presentation. |
| `--max-chars` | **[0.11] Remove in favor of the token budget.** Two mutually exclusive size units add little value to an agent-facing read command. |
| `--detail brief` | **[0.10.x add; 0.11 remove old mode] Add `--outline`, returning heading titles/slugs without the body.** Finding a section is a concrete operation, not a verbosity level. |
| Other `--detail` modes, including 0.10's `agent` projection | **[0.11] Remove in favor of one consistent result with content, ref, and useful metadata.** Scripts and agents should not need different result shapes for the same read. |
| `--project` | **[0.10.x / 0.11] Retain explicit usage attribution, including `none`, and clarify that it does not filter or change content.** Wrappers reading outside a project's working directory still need correct attribution. |
| `--format` | **[0.11] Retain JSON and text only, with the same content-selection behavior.** Structured consumption and direct reading cover show's normal uses. |
| `--output` | **[0.11] Remove; use shell redirection.** Writing stdout to a file does not need another show option. |
| Shared `--config` | **[0.10.x add; retain in 0.11] Offer the normal installation/config selector without changing existing path resolution when omitted.** Explicit reads must still resolve against the intended installation. |
| `--quiet` / `-q`, `--verbose` | **[0.10.x retain; 0.11 conflict error] Keep shared stderr controls and reject simultaneous use in 0.11.** Diagnostics should neither change the returned content nor compete with each other. |
| `--help` / `-h` | **[0.10.x] Add concise whole-asset, fragment, outline, and bounded-read examples as replacements land.** These examples explain the complete content-selection surface before migration. |

- [ ] **[0.10.x new flags; 0.11 old-mode cleanup] Reject unsupported combinations of the new show controls, including lead without a Markdown fragment and outline with content-only controls.** A successful read must honor the requested selection without adding raw/debug variants to show.

## Learning configuration cleanup

- [ ] **[0.10.x / 0.11] Keep ordinary controls for enablement, scope, budgets, model/connection selection, retention, and sync/push behavior on the supported surface where they have demonstrated use.** Operating an installation should not require experimental tuning or lose controls over cost and publication.
- [ ] **[0.10.x aliases; 0.11 old-path removal] Retain research-used process isolation, quality-gate toggles, reflect defect filters, and extraction/session-indexing controls under experimental configuration.** The current reflect, distill, extract, and bakeoff evaluators use these controls to distinguish treatments.
- [ ] **[0.10.x audit/aliases; 0.11 removal] Audit per-process runner overrides and remaining thresholds, chunk sizes, filters, and maintenance knobs individually; move demonstrated research controls under `experimental` and remove controls without demonstrated product or research value.** Moving every old knob wholesale would preserve the sprawl under a different heading.
- [ ] **[0.11] Remove a configuration control only when doing so leaves the existing process implementation and effective research settings intact.** Deleting a schema field must not discard a working override or become an excuse to simplify the underlying algorithm.
- [ ] **[0.10.x] Treat new experimental aliases as optional overrides of unchanged defaults, preserving the existing `experimental.improveAutonomy` gate separately.** Relocation must not turn currently enabled learning processes off or enable autonomous writes.
- [ ] **[0.10.x] Translate old and new settings at the configuration boundary, preserving values, precedence, false/zero/empty overrides, and conflict diagnostics; remove old-key support only in 0.11.** The same experiment should reach the same engine inputs after migration without an internal refactor.
- [ ] **[0.10.x rollout; 0.11 cleanup] Update help, examples, config templates, and schema descriptions together, showing replacements and deprecations as they land.** Hiding flags from help alone does not produce a smaller supported surface.
- [ ] **[0.10.x, repeat on 0.11] Verify migrated effective plans, model requests, side effects, and recorded evidence with deterministic fixtures/replays, updating evaluator adapters without changing cases or scoring.** Interface compatibility should be established without introducing a new treatment into the research.

## Command and argument usage metrics

- [x] **[0.10.x] Capture every CLI invocation by default at the shared entry point, including nested commands, help/version, invalid arguments, startup failures, and cancellations, without sampling.** Starting before the removals supplies a baseline of actual command attempts.
- [x] **[0.10.x] Record command paths and every supplied argument's identity, positional role, repeated occurrences, negation, and canonical spelling while distinguishing explicit input from defaults.** This reveals which flags and combinations callers actually choose instead of counting parser-injected defaults as demand.
- [x] **[0.10.x] Record the resolved asset type for `run` and separate AKM options from asset inputs and arguments after `--`.** A unified entry point must still reveal which execution capabilities are used without attributing child-program flags to AKM.
- [x] **[0.10.x] Attach invocation identity, timestamp, CLI version, local instance identity, known caller/source, duration, exit status, and structured outcome/error category.** Version comparisons, adoption breadth, and failure rates distinguish useful features from repeatedly attempted or brittle ones.
- [x] **[0.10.x] Retain safe argument values such as declared enums and booleans, recording presence/type or redaction markers for secrets, free text, paths, URLs, and opaque payloads.** Feature analysis needs argument usage without turning metrics into a second store of prompts, credentials, or command content.
- [x] **[0.10.x collection/retention; 0.11 preservation] Store usage locally with additive metrics storage, retain release-comparable aggregates after detailed records expire, and preserve them through the 0.11 storage migration.** Future release decisions require durable evidence and a clear distinction between unused and unobserved surfaces.
- [x] **[0.10.x] Add command/argument counts, combinations, per-instance adoption, errors, and duration summaries to `doctor metrics`, with version/source/window filters and a stable JSON export for lab aggregation.** One report should show what is used, where it is used, and where callers encounter friction.
- [x] **[0.10.x / 0.11] Keep user/agent, scheduled, improvement-internal, audit/evaluation, and unknown traffic distinguishable, with command metrics separate from learning feedback and ranking inputs.** Background repetition and measurement activity must not masquerade as product demand or alter the learning processes.
- [x] **[0.10.x, repeat on 0.11] Verify exactly-once invocation counting, redaction, early-exit coverage, concurrent writes, rollup/export deduplication, and bounded overhead through the real CLI entry point.** Collection failures must preserve command behavior and appear as coverage gaps rather than successful executions or evidence of zero usage.

## Release fixes and completion

- [ ] **[0.11] Track qualified bundle/task identity through task reservation and dispatch.** A running task in one bundle must not suppress a same-named task in another bundle.
- [ ] **[0.11] Preserve legacy-ref usage history or block destructive indexing until migration completes after a manual package upgrade.** Missing a migration step should not silently erase historical evidence.
- [ ] **[0.11] Reconcile learning changes already on the branch against the research baseline, including removed `improve.stateGc` and relocated inference settings.** An existing branch change is not evidence that dropping a control preserves behavior.
- [ ] **[0.11] Rehearse upgrades with matching plugins, custom config paths, and existing OS scheduler entries.** Unit-level compatibility does not prove that an installed CLI, its plugins, and scheduled jobs still operate on the same installation.
- [ ] **[0.11] Detect incompatible active workflow runs before upgrade and provide a clear drain, finish, or restart procedure.** Abandoning a frozen run and starting fresh can repeat work or side effects.
- [ ] **[0.11] Stabilize the qualified task and workflow core and explicitly retain-as-experimental or remove each remaining questionable capability, including child workflows.** Users need precise supported capabilities rather than blanket uncertainty around an entire feature family.
- [ ] **[0.11] Publish the stable 0.11 core contract and the separate evolving doctor boundary, with matching help, examples, schemas, and stability documentation.** Users should know which flags, result fields, and defaults they can depend on and where diagnostic churn is expected.
- [ ] **[0.11] Resolve every migration-guide marker against the final implementation and record the first supporting versions, exact replacements, and verified upgrade behavior.** The draft must become actionable release documentation before 0.11.0 ships.
- [ ] **[0.11] Run the platform, packaged-artifact, and upgrade gates on the exact release candidate.** The latest merge's green fast checks do not cover the deferred release-specific validations.
- [ ] **[0.11] Freeze feature scope after these cuts and decisions, limiting remaining release work to correctness, compatibility, and usability fixes.** A bounded stabilization period makes the release easier to validate and gives the supported surface time to settle.
