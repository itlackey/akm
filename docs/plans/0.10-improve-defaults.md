# 0.10 improve defaults: measurement plan

Owner direction, 2026-10-09. Issue: #1094. Part of the [0.10 stabilization plan](0.10-stabilization-plan.md).

## Goal

Choose the improve processes and settings that ship on by default in 0.10 from measurements, not usage counts. Every item below ends with a verdict and the run that backs it: **on by default**, **configurable**, or **removed**. The same runs are kept as a repeatable check for later 0.10 changes.

## Rules

- **Public assets only.** Every case is fictional or from the public library in akm-eval, so a cloud model may run it.
- **Models.** `gpt-5.6-terra` (OpenAI API) screens. Any configuration that differs from the baseline is confirmed on the production engine, `qwen3.8-27b` on krang.
- **Baseline.** akm 0.9.30 with the built-in `default` strategy. Compare only runs of the same akm build.
- **Two stages.** Screen every configuration once on a `--limit` subset. Rerun only the ones that differ, 3 times on the full set.
- **Decision rule.**
  - On by default: the main metric beats repeat noise (the min–max ranges do not overlap) and harm does not rise.
  - Configurable: mixed results, or results that depend on the model.
  - Removed: no measurable effect, or broken.
  - A consolidation or forgetting mechanism is never removed for low usage alone.
- **Cheap first.** A knob that only changes planning order is measured with `akm improve --dry-run`, which makes no model calls.
- **akm-eval changes are long-term only.** Code needed only for this sweep is a temporary wrapper in akm-eval-private `sweeps/0.10-improve-defaults/`, removed when the sweep is done.

## akm-eval changes (long-term)

- `--strategy NAME` and `--config-patch FILE` in `lib/akm`, for nightly, consolidate, distill, reflect and promotion. The patch is deep-merged into the sandbox config.
- `--repeat` for every eval, and `n_errored` in the nightly summary.
- consolidate `--pool`: a whole-pool case, as a real night consolidates.
- `scripts/matrix`: runs a matrix file (eval × configuration × model × repeats) in the two stages above and writes a decision table.
