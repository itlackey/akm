# 0.10 stabilization plan

Owner direction, 2026-10-08. Tracking epic: #1097.

## Goal

By the end of the 0.10 series every part of akm is either **Stable** or **removed**. That covers:

- **Product surface:** every command, flag, config key and asset format.
- **Default configuration:** the improve processes and settings a new install gets.
- **Implementation:** hardened, cleaned up and simplified.

0.11 then handles only the hard breaks still needed before 1.0.

## Rules for every decision

1. **Measure before removing anything that may hold value.** A feature is cut because the numbers say it adds nothing, not because one installation does not use it. Low usage alone never removes a forgetting or consolidation mechanism.
2. **Defaults come from evals.** The improve processes, strategies and settings that ship on by default are chosen from akm-eval results, testing and refinement, so users get the best configuration out of the box.
3. **Subtract once the measurements settle it.** What is not on by default and not worth configuring is removed. The machinery that served only removed options goes with it.
4. **Every Experimental feature leaves Experimental during 0.10.** It is either promoted, with tests that exercise it for real, or removed.
5. **Supported upgrade floor: 0.9.15.** 0.10 reads what 0.9.15 and later wrote; older installs run `akm migrate apply` from 0.9.x first. Shims for older formats can go.
6. **One gate for evidence: akm-eval.** Each decision cites a run: repeat runs, the labelled own sets, and the build recorded in `summary.json`. Problems found with the evals go in akm-eval-private `ISSUES.md`.

## Order of work

1. **Measure and decide.** Run the improve, workflow and adapter measurements. Record a keep / configure / remove decision for each item in its issue, with the run that supports it.
2. **Cut, merge and refactor.** Apply the decisions, the cuts in #1091 that need no measurement, the harness pattern, and the SDK-first work. Each change ships as its own PR; nothing adds new surface without the owner's approval.
3. **Set the defaults.** Ship the measured default improve configuration. Re-run the nightly eval and production nightlies to confirm it.
4. **Stabilize and document.** Promote what survived in STABILITY.md. Make the docs and help text match. Contract tests cover every Stable surface.
5. **Hand over to 0.11.** List the hard breaks still needed before 1.0, such as removals that need a deprecation window and format changes. Nothing else is planned for 0.11.

## Done when

- STABILITY.md lists no Experimental surface except ones the owner explicitly keeps there into 0.11, each with a reason.
- A fresh install's improve configuration is the measured default, and every remaining setting is documented with what it does.
- Every Stable surface has a contract test, and its docs match its behaviour.
- The removed features, keys and shims are gone from code, schema and docs; the 0.9.15 upgrade floor is documented.
