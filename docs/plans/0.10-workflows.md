# 0.10 workflows: core feature set and trim candidates

Phase 1 of [#1096](https://github.com/itlackey/akm/issues/1096). Workflows are
**Experimental** through 0.10 (STABILITY.md, "Experimental"). 0.10 stabilizes
them, trims what is not useful, and records promote-or-remove before 0.11.

This document only measures and recommends. **Nothing is removed by the PR that
adds it.** The owner decides from the table below.

## Core feature set

The set the owner's scheduled workflows actually use (#1091 audit, re-checked
against `~/akm/workflows`, 9 files): everything below, and nothing else.

| Feature | Behaviour pinned by `tests/integration/workflows/core-feature-set.test.ts` |
| --- | --- |
| `params` | Typed `--<name>` flags (`workflow run`) or task `inputs:` (`task run`) become `run.params` (an integer flag stays an integer); shown to every unit as `Run parameters`. |
| `steps` | Run in order; a run stopped after N steps (`--max-steps`) resumes at the next step without re-dispatching earlier ones. |
| `inputs: [steps.x.output]` | The upstream typed artifact is attached to the downstream unit's prompt. |
| `output` / `unit.output` | JSON Schema on the promoted artifact. One schema miss gets a corrective re-dispatch carrying the validation error; a second miss fails the step and the run stops before the next step. |
| `defaults.engine` | Units dispatch on the workflow's own engine, never the install-wide `defaults.engine`. Dispatch goes through the opencode-sdk harness. |
| `### gate` + `workflow.judgeEngine` | A step with a rubric is judged on its artifact by the judge engine (one call per gated step). `complete: false` and a malformed verdict both stop the run (fail closed). |
| task -> workflow | Three entry points are covered: `akm workflow run <ref>`, a v4 task with `uses: workflows/<ref>` (`akm task run`), and a v4 task whose `run:` is the literal `akm workflow run workflows/<ref> --<param> ... --skip-if-locked` (the owner's shape), executed as a real subprocess. A task whose `run:` names a removed verb (`workflow next`) must fail, not pass. |

Fixtures are neutral. The agent cases use a fake `createOpencode` server
(`__setServerFactory`, the pattern from `tests/opencode-sdk-runner.test.ts`) that
keys its answer on the model the server was started with, so each assertion says
which engine served a call. The subprocess cases use exec units (below) because
a real child process cannot reach the in-process fake server; they still cover
params (`AKM_PARAMS`), `inputs:` (`AKM_INPUTS`) and typed `unit.output`.

### Gaps in the core set (found while writing the tests)

1. **A param's `default:` is never applied.** The schema accepts it, but it is a
   JSON Schema annotation the engine ignores (workflow-schema.md, "enforced
   subset"): an omitted param is absent from `run.params` and the unit prompt
   says `Run parameters: {}`. `~/akm/workflows/homelab-spot-check.md` restates its
   defaults in prose because of this. Stabilizing means either applying defaults
   at run start or rejecting `default:` in `params`. The test pins today's
   behaviour so the fix is a visible change. Params are also never "required".
2. **Runs are scoped by working directory.** A task runs in its own cwd, so its
   run is invisible to `akm workflow list` from elsewhere unless `--all-scopes`
   is passed. OpenPalm's boot probe uses `workflow list --active`.
3. **Doc drift on the tier.** `docs/reference/workflows.md:9`,
   `docs/architecture/workflow-engine.md:12` and `docs/reference/cli.md:832,924`
   still call `workflow run` "Stable"; STABILITY.md and `cli.md:801` say
   Experimental.

## Unused features: size, tests, callers, recommendation

**Method.** Source lines are raw `wc -l` lines (the measure #1091 used,
13,551 for `src/workflows`): whole files where a file exists only for the
feature, plus named declarations and an estimate for inline branches in shared
files, so treat them as +/-15%. Test lines are the dedicated test files in full
plus feature-token lines elsewhere in workflow-related tests. **STABILITY tier**
is "Experimental" for every row: STABILITY.md tiers the whole `akm workflow`
surface, asset format and engine together, with no per-feature entries.

**Callers searched** (all negative unless a row says otherwise):

- Owner's bundle: `~/akm/workflows` (9) and `~/akm/tasks` (15; one calls a
  workflow, `curate-to-wiki` via `run:`). Keys used: `params`, `steps`,
  `inputs` (5 files), `output` (6), `defaults` (4), `### gate` (1: `research-to-knowledge`,
  6 gates; `workflow.judgeEngine` is configured). Real run
  history in `state.db`: `curate-to-wiki` 27 runs (latest 2026-10-09),
  `homelab-spot-check` 10, `portfolio-review` 10, `system-health-report` 13,
  `homelab-health-review` 4, `research-to-knowledge` 5. Older May-June runs
  (`github-issues-parallel-implementer`, `three-judge-design-gate`, ...) predate
  the native engine and were driven by the removed `next/complete` protocol.
- OpenPalm: local checkout (`refactor/lean-stack`, 2026-10-01) and GitHub
  `main` (2026-09-11) and `release/0.14.0-beta.2`. Only `main` references
  workflows: `akm workflow list --active` (boot health probe),
  `akm workflow run|status` in the assistant instructions, and task `uses:
  workflows/<name>` with empty params in `markdown-task.ts`. No workflow assets.
  The lean-stack and 0.14 branches have no workflow references at all.
- akm-plugins `origin/main` (2026-10-09): `akm workflow list --active` and

- akm-eval `main` (2026-10-10): 12 workflow files, all static retrieval/AB
  corpus assets using only `params`, `steps`, `inputs`, `output`; nothing runs
  them through the engine.
- akm repo itself: the `workflow create` template uses `params`, `steps`,
  `inputs`, `### gate`. Fixtures under `tests/fixtures/execution-contracts`
  exercise the rest.

## Open points for the owner

- Decide the three-way **composition cut** (child workflows + `outputs:` + YAML
  with task composition and script targets) as one unit; it cannot be split
  cleanly because YAML is the only carrier of `uses:`.
- Decide **param defaults** (apply or reject) before promotion; it is the only
  core-set gap.
- Fix the **tier wording** in the four doc places listed above whichever way the
  rest goes.
