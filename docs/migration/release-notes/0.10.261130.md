# akm v0.10.261130 migration notes

`akm upgrade` runs `akm migrate apply` after it installs this release. Nothing
below is done for you by that run: each is a change you make when you are ready,
before 0.11 removes the old form.

## Workflows become tasks

Workflows are deprecated and are removed in 0.11. `akm doctor` and
`akm migrate status` count the workflow files left in your writable bundles.

```sh
akm migrate status workflows/weekly.md   # what the file becomes, or why it cannot convert
akm migrate apply workflows/weekly.md    # makes tasks/weekly.yml; the workflow file stays
akm doctor explain tasks/weekly          # the check a start makes of the new task
```

A file that cannot convert is `blocked` with `detail` and `guidance` that say
what to change in the workflow. The usual case is a `${...}` in a step's text
that is not an input or an earlier step: write a shell or environment variable
without braces (`$XDG_CACHE_HOME`) or in words. Run the task once, point the task
files and skills that named `workflows/<name>` at `tasks/<name>`, then delete the
workflow file. The full table is in
[Converting a workflow](../v0.10-to-v0.11.md#converting-a-workflow).

## Task source v5 is opt-in

`akm migrate apply tasks/<name>.yml` converts a named version 4 task file to
`version: 5-beta.1`; a file that is not named stays at version 4 and keeps
running. `akm migrate status tasks/<name>.yml` shows the result first. See
[Converting v4 to v5](../../reference/tasks.md#converting-v4-to-v5).

## `akm env run` and `akm secret run`

Both still work and print a notice; 0.11 removes them. Put the command in a
script asset and run it with the env asset or secret:

```sh
akm run --env env/prod scripts/report.ts --since 1d
akm run --secret secrets/token:API_TOKEN scripts/report.ts
```

In a task, give the step `env: [env/prod]` or `secret: [secrets/token:API_TOKEN]`
and drop the wrapper from its command. `env run --only` and `--except` have no
replacement: keep the variables a command needs in an env asset of their own.

## Smaller changes

- `akm migrate apply --dry-run` is deprecated: `akm migrate status [<file>...]`
  is the preview.
- A plain `akm upgrade` follows the channel the installed akm is on. An install
  on a prerelease stays on `next`; `--channel latest --allow-downgrade` leaves it.
- A step of a steps task no longer records a `summary` in the run result or
  task history.
