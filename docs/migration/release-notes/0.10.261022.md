# akm v0.10.261022 migration notes

This release needs no configuration or database-schema migration from the
previous stable 0.10 release.

## Document classification

Documents inside typed directories such as `knowledge/` and `memories/` keep
that type when their text quotes `$ARGUMENTS`. On the next ordinary `akm index`,
the native AKM adapter re-reads affected directories and replaces the old
placeholder-inferred command refs with document refs. Source files are not
rewritten, and no full index reset is required. Update any scripts or saved
links that explicitly used those old misclassified command refs.

If a file is intended to be a command, put it under `commands/` or use the
existing explicit `agent` frontmatter. Placeholder discovery in untyped
directories is unchanged. Skills named `knowledge`, `memories`, or `commands`
need no rename; their false health warning is fixed without reindexing.

## Local UI

Restart an existing `akm ui` process after upgrading to load the new assets.
The UI keeps its existing configuration and Bundles layout. Editing conflicts
now require a separate **Overwrite with my draft** action after reviewing the
current contents; an ordinary Save retry does not overwrite newer work.
Operational charts and their data tables work offline with existing recorded
data. No service, telemetry, or additional setup is required.

For upgrades from 0.9, follow the
[0.9 to 0.10 migration guide](../v0.9-to-v0.10.md).
